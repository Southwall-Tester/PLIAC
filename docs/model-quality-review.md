# 教学模型固定案例评测

## 范围与边界

1. `src/pliac/tutor_quality.py` 提供七个合成参考案例，使用不可变验收课程与临时匿名学习者构造真实教学上下文，不读取真实学生记录，不修改正式课程。案例包版本为 2。
2. 案例覆盖已有小样本中暴露的编号判断过度概括、同题不同基础的教学差异、自评与证据边界、优先实验、用户越权请求及来源正文注入。来源注入只在复制后的检索上下文中追加明确标记的合成攻击片段，不改动不可变验收课程；它覆盖检索后模型输入边界，不代表已经验证文件上传解析全链路。不是正式机器学习课程的完整教学评测，也不替代 A01—A16 全部验收。
3. 所有结果的教学语义状态初始均为 `not_reviewed`。引用可定位、字段合格不代表解释正确、教学有效或学生已掌握。成对基础案例应一起比较，不能只看两个响应是否文字不同。

## 执行方式

1. 在仓库根目录执行 `.venv/Scripts/python.exe scripts/verify_tutor_quality.py`，默认仅列出案例，不读取模型配置或调用供应商。
2. 确认模型、预算与合成数据传输范围后，可显式执行 `.venv/Scripts/python.exe scripts/verify_tutor_quality.py --live --case identifier-boundary --max-cases 1`。多个案例重复填写 `--case`。数量上限只限制应用层案例数；供应商内部重试仍可能产生多次请求，不是金额或 token 上限。
3. 真实执行顺序调用现有教学生成函数，每次写入唯一报告文件至 `outputs/verification/tutor-quality-<编号>.json`，不覆盖旧评测。报告包含固定评审要点、实际输入上下文、生成内容、模型标识、耗时和结构结果，不序列化 API 配置或完整供应商错误。
4. 单例失败记录异常类型并继续后续已选案例，不伪造响应或自动追加案例。应先检查配置，再在明确预算范围内执行；本轮开发仅运行模拟响应测试和默认案例列举。

## 内容评审与后续补齐

1. 逐项对照报告中的课程来源和案例要求，记录问题原句、问题原因及修复后复测。对于编号案例，要检查是否保留适用条件，不能用简单禁词匹配代替语义判断。
2. 对比初学者与有训练经验者的活动顺序、例子、解释深度和核验问题；如果只换称呼，不算实现有依据的个性化。
3. 这些是开发阶段的教学质量验证，不是在学生学习时重新加入逐轮人工审核或发布门槛。
4. 正式单元确认后，还需补充该单元的教师参考答案、受助与迁移样例、冲突证据、知识更新、来源不足和多轮闭环评测。当前案例包没有宣称已覆盖这些内容或已证明真实模型可靠。
