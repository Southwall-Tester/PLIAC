## 1 项目定位与决策边界

### 1.1 我们要建设什么

平台服务修读或自主学习机器学习的学生，不限定本科生。以自主学习为主，由智能体围绕课程知识、学生目标与学习证据，持续决定教什么、怎样教、如何练、怎样检验和下一步如何调整。平台是智能教师支持的课程学习空间，不是静态课程目录附加聊天窗口，也不是只输出一次能力报告的评估工具。

个性化学习是产品主线；能力评估、认知诊断和知识追踪是实现可信个性化的支撑机制。学生画像影响路径、深度、案例、表达和支架，不改变学科事实，也不因为学生偏好而降低原定能力要求。

### 1.2 已明确的产品要求

1. 首轮领域限定机器学习。学生可提出系统学习、补某个知识点、完成某类任务等目标，由智能体协商可实现范围；不开放任意陌生领域即时建课。
2. 学生可以坚持先学某个知识点或先做 Lab。智能体说明前置缺口并提供帮助；未验证部分保留待核验，不把跳过解释为掌握。
3. 智能体全程主控，个人教学内容和学习状态在线调整，不设置逐次人工审核或人工发布关卡。
4. 保留多来源、多形式材料设计。首轮重点做好动态讲义、对话、练习与现有 ML Lab；既有视频、PDF、课件按统一材料契约接入，不承诺首轮自动生成所有媒体。
5. 学习者采用稳定匿名标识；实现单次画像及简单长期画像，保存个人教材、笔记、有效解释和报告。在线保存浏览与 Word／PDF 导出均属于目标交付。
6. 首轮摄像头为可选授权采集，结合活动时间和基础线索提供帮助；只记录平台内操作，不进行全屏录制。
7. 首轮不宣称严格微表情识别或心理诊断。拒绝摄像头不影响正常学习，也不降低掌握判断。
8. 前端方向为 React、TypeScript、Vite，沿用 FastAPI 后端。三套主题共用结构和功能，用户可以切换。
9. 学生界面与管理后台分离，不再额外建设一套教师授课端。后台用于知识资源、任务标准、运行状态和证据回查，不逐次接管教学。
10. 比赛前希望同时具备 Demo 和小规模真实试用。具体截止日、试用安排及提交清单需另核实，不在本指南中猜测。

### 1.3 仍然不能当作已确认的事项

1. 首个正式课程单元尚未最终确定。“文本表示与语言模型基础”是否为正式章节仍待确认。建议优先采用与现有 Lab 衔接紧密的“数据划分与过拟合泛化”小单元，但这不是已经确定的课程名称。
2. 四位成员可以参与，具体责任人尚未分配。
3. 作品展示名称另行设计，大创项目名称暂不修改。
4. 正式试用部署地点、身份恢复方式、模型预算、视频保存期限与删除责任人尚未确定。
5. 用户此前认为不需要伦理审查，不等于已完成学校程序核实。指南不擅自认定必须审查或已经豁免；涉及真实学生与可识别视频前，由负责人确认适用的校内要求和授权安排。

| 学习状态 | 起点资料、自评、作答、提示、证据和诊断分离，版本与幂等机制 | 保留这些约束，增加模型诊断和主控决策 |
| 讲义生成 | `margin.py` 复用 LearnMargin，按课程材料组织来源与生成 | 增加学习者目标、画像、活动上下文及个人教材版本，不能把课程讲义直接称为个性化闭环 |
| 学习编排 | `workspace.py` 当前以规则选择节点，明确不做模型掌握决策 | 引入真实模型教学主控，并保留规则工具和状态服务 |
| ML Lab | 真实 scikit-learn 有界参数实验、任务合同、提示与复现导出 | 解耦演示课程绑定，补充智能辅导和解释性诊断 |
| 前端 | 多个静态页面和独立入口 | 新建 React 学生工作台，逐步替换，避免一次性重写所有后台页面 |
| 摄像头 | 本次未核验到 PLIAC 完整采集与教学联动实现 | 在明确授权、存储与隔离后建设；ChatEval 仅作参考，复用前核对许可 |

### 2.3 选择原仓库分支而不是新仓库

改动幅度较大，尤其涉及学生前端、教学主控和评价规则，但课程、资料、实验引擎与事务记录并非无效代码。新仓库会引入重复接口、双份课程数据、历史断裂和更高的联调成本。因此选择原仓库中的独立分支。

继续使用已经存在的 `feat/agent-learning-platform`，不重复创建分支或新仓库。本次只修订指南，不提交、不推送、不修改业务代码。接续开发先核对未提交改动、未跟踪文件和当前运行服务，保全工作区；远端差异尚未核验，不直接拉取合并或覆盖本地。若确需保持旧平台独立运行，可另行安排同仓库独立工作目录；未提交代码、密钥和运行数据不会自动随之复制。

1. 保留现有 `src/learning_agent`、`src/pliac` 和运行数据路径，不以重命名目录代替架构升级。
2. 沿用已有 `web/` React 前端及 `/app` 独立入口，旧页面阶段保留作回退与对照；不再新建第二套学生前端。
3. 每一阶段保持可启动、可验证；阶段提交范围围绕明确功能，不将无关清理混入改造。
4. 切换正式入口前验证旧链接兼容和新前端深链接刷新，API 路由不能被单页应用回退吞掉。
5. 代码回退不等于数据回退。数据升级需版本、备份和恢复演练；新数据结构与旧代码不兼容时，不可仅切换分支就声称完成回滚。
6. 不修改 ChatEval 或 DeepTutor 原仓库。不复制真实学生数据、密钥和无明确授权的第三方素材。

### 2.4 必须显式消解的旧规则冲突

历史 `AGENTS.md` 和旧工作流要求正式课程人工审核发布；v3 对共享知识更新也保留审核表述。当前仓库规则已明确采用自动来源、结构和证据验证。仍须检查实际入口、接口和测试是否一致，不能仅凭规则文件已改就认定旧人工关卡已全部替换。

新规则是：自动结构验证、来源核验、依赖检查与版本化生效；未通过的内容保持不可用或证据不足，不转成等待人工审批才能继续学习。管理员仍可以维护、纠错和回滚，但人工介入不是每次教学的必要步骤。

保留的底线是：原始证据不可伪造；模型诊断不得冒充人工复核；学生对话不能直接改写公共知识；任务完成不能自动等同于概念掌握。旧测试中专门断言人工复核的用例需替换为新自动评价规则，不能为了新功能通过而删除所有证据约束。

## 3 学习闭环与状态转换

### 3.1 首次进入与再次进入

首次进入先提出目标，再给出与目标相关的少量自评和必要诊断。自评选项可保留“尚未学过、学过但不确定、能够独立解释和应用”，但不要求一次填写整个课程所有知识点。智能体通过追问、短题或任务确定足够的学习起点；证据不足就标明待核验，不追求一次测出完整能力。

再次进入先恢复目标、阅读位置、未完成任务、草稿和相关记忆；仅对过时或存在冲突的关键状态补充核验。不每次重做初始问卷，也不默认旧掌握结论永久有效。

### 3.2 主循环

1. 明确当前目标和完成要求。
2. 读取目标知识子图、可信材料、当前画像与相关历史。
3. 智能体选择下一教学活动，并说明简短理由与需要收集的证据。
4. 在统一工作台生成或展示讲解、材料、对话、练习或实验。
5. 保存学生原始作答、操作结果、提示使用与技术状态。
6. 按事先确定的标准进行客观检查或解释性诊断，记录依据和不确定项。
7. 更新画像与记忆，决定继续、补学、换解释、迁移核验或阶段总结。
8. 随时可中断和恢复；阶段目标达成后形成教材与报告，不要求必须学完整门课才能得到成果。

### 3.3 分清不同状态

| 状态类别 | 示例 | 不能替代什么 |
| --- | --- | --- |
| 内容位置 | 正在阅读第 3 段、视频第 120 秒 | 不等于完成学习或理解 |
| 活动进度 | 未开始、进行中、已提交、已完成 | 不等于知识掌握 |
| 知识判断 | 待核验、证据支持部分理解、证据支持掌握、需补学 | 不由页面点击数决定 |
| 复习安排 | 建议复习、复测到期 | 不必直接把原掌握结论改成不会 |
| 技术状态 | 生成中、失败、取消、网络断开 | 不作为学生能力不足的证据 |

跳过、自评、阅读完成、提示后答对、独立答对和独立迁移必须能够分别记录。连续出错可触发帮助，但不能未经核验就断定心理状态或固定能力水平。

## 4 知识图谱与知识库

### 4.1 两者都需要但不必一开始建设重型基础设施

图谱负责概念及关系，知识库负责定义、解释、例题、误解、任务标准和来源。现有资料与讲义体系可作为知识库基础，不能因为没有专门的向量数据库就认定没有知识库，也不能认为只要有可视化节点就足够教学。

首轮建议先基于已关联课程的来源片段进行范围检索和排序；只有当材料规模和检索评测证明有需要时，再增加向量检索或混合检索。不把采用 GraphRAG、Neo4j 或某个向量库设为目标本身。

### 4.2 建议的最小知识对象

1. 知识点：稳定 ID、名称、定义、别名、适用范围、课程归属、目标能力、来源引用和版本。
2. 关系：两个端点、关系类型、方向、条件、来源、验证结果与版本。只有经验证的先修关系约束学习顺序；相关、易混淆、章节包含及共现不得冒充先修。
3. 来源单元：资源 ID、版本、页码或片段位置、正文、标题、可访问性、使用权限和内容指纹。
4. 教学资源：目标知识、形式、深度、前置要求、适用片段与使用位置。视频按片段、PDF 按页或段落关联，不只挂一个整文件链接。
5. 评价任务：目标知识与能力、题面或活动合同、评价要点、提示、独立性要求、版本及已曝光记录。

### 4.3 建构与更新流程

资料解析 → 保留出处 → 候选概念抽取 → 同义归一与同名区分 → 关系抽取 → 结构及语义检查 → 形成可用知识版本 → 教学使用 → 根据缺口形成下一版候选。

自动检查至少覆盖引用可定位、概念非碎片、关系端点有效、先修环路、相互冲突的定义与不合理的过度合并。程序检查能保证格式或引用存在，不能单独证明语义正确。模型复核也可能出错，应通过固定样本抽查评估其质量；抽查是研发验证，不是逐个学生在线等待审核。

公共知识变更与个人教材调整分开。当前学生会话固定引用所用知识版本；新版本不抹去旧教材、旧题面及历史判断。严重知识错误可以禁用后续使用并提示影响，但历史证据仍需可追溯。

## 5 智能体运行架构

### 5.1 先模块化单体不堆砌多智能体系统

建议在现有 FastAPI 中实现统一教学主控及可调用服务。知识检索、教学生成、诊断、记忆和实验是职责模块，不必分别部署多个智能体、多个后端或消息系统。只有实际出现并发、独立扩展或隔离需求时再拆分。

| 模块 | 输入 | 输出和责任 |
| --- | --- | --- |
| 上下文装配 | 学习目标、当前活动、知识版本、相关画像和历史 | 有范围的模型输入，排除其他学生数据与无关历史 |
| 教学主控 | 上下文及关键事件 | 下一活动、理由摘要、需要的材料和核验目标 |
| 内容与资源 | 教学动作、知识及来源、表达偏好 | 当前小节、案例、图示说明、材料引用与后续任务 |
| 评价服务 | 原始证据、固定评价标准、提示与曝光状态 | 逐项判断、证据引用、不确定项及建议动作 |
| 记忆服务 | 已提交的活动、诊断和学生修正 | 会话摘要、个人教材索引、相关长期记忆 |
| 实践服务 | 活动合同、允许的参数和会话 | 真实运行结果、工具错误与可复现记录 |
| 状态服务 | 经验证的操作及预期版本 | 原子写入、幂等回执、版本冲突处理和恢复 |

### 5.2 决策记录与工具边界

每次教学决策保存目标、活动 ID、引用知识与证据、动作类型、理由摘要、下一次核验目标、模型与提示模板版本。保存的是可检查的决策摘要，不要求暴露模型内部思维过程。

模型可以建议补学、生成解释、安排练习和解释评价；实际读写记录、执行 Lab、更新状态和访问材料由服务端工具验证后完成。模型不能获得任意文件权限、任意代码执行或跨学生查询能力。

资料与学生输入均作为数据，不作为提升权限的系统指令。引用资料中的“忽略规则”等文字不能改变教学主控的工具权限。前端不接受模型直接输出可任意执行的脚本来控制页面；教学内容通过受限内容结构和安全渲染器展示。

### 5.3 尽量可靠而不是承诺模型永不失败

1. 统一模型网关管理超时、限流、取消、结构校验、调用记录和费用，密钥只在服务端。
2. 对格式错误允许有限次数修复；对网络错误采用有上限的重试。具体次数和时限通过试跑制定，不无限重试。
3. 教学动作和诊断必须校验引用与作用范围；模型自报高置信不等于已校准的准确率。
4. 模型不可用时，学生仍可查看已保存内容、继续支持离线规则的操作并保存草稿；依赖模型的诊断明确待完成，不用固定回复伪装真实模型运行。
5. 长任务保存 job_id 与过程状态，连接断开不等于任务不存在。重新进入先查询结果，避免重复生成、重复收费或重复记证据。
6. 不在模型生成期间持有长时间的数据写锁。读取版本后生成，提交时再检查版本；如学生已切换课程或活动，结果不能写入错误上下文。
7. 模型选择以真实教学小样本评测决定，不凭品牌或参数量认定最好。对话、生成和诊断可先用同一可靠模型，必要时再拆分。

## 6 学习者画像 认知诊断与知识追踪

### 6.1 画像结构

1. 背景与偏好：学生声明的学习目标、必要基础、表达偏好和兴趣，可修正，不直接作为掌握证据。
2. 知识状态：按知识点保存原始证据引用、诊断、误解、独立性、提示依赖、更新时间与适用版本。
3. 能力表现：区分解释、辨析、应用、操作、迁移等任务要求。表现范围限于已观察的课程与任务，不上升为智力或人格标签。
4. 活动上下文：当前章节、材料版本、阅读位置、未完成任务、草稿、Lab 参数与最近问题。
5. 长期记忆：阶段摘要、稳定偏好、反复出现的误解、有效解释和相关证据索引。长期记忆是可检索摘要，不把全部聊天拼进每次提示词。

### 6.2 方法依据与本项目的采用边界

采用证据中心设计的思路，将“希望判断的能力”“能支持判断的证据”“产生证据的任务”对应起来。ETS 的 ECD 文献提供这些职责划分的依据，但不替我们生成适合机器学习课程的评价标准。[参考 1]

认知诊断回答当前有哪些掌握与误解证据；知识追踪回答这些状态如何随着学习序列变化。首轮先实现明确的任务—知识点映射、可解释评价和时间序列记录。BKT 可作为适合客观题或明确技能练习的基线候选，先以独立核验数据进行离线评估，不直接用未经校准的概率给所有开放题判掌握。[参考 2]

不把简单正确率称为 BKT，不把大模型一段评价称为已经训练验证的认知诊断模型。DINA、DKT 或其他复杂模型若无匹配的数据、参数估计和验证，不作为首轮必须实现的标签。

### 6.3 掌握判定流程

1. 在学生作答前确定知识目标、能力要求、任务版本、评价要点与允许帮助程度。
2. 客观题和可执行实验优先用明确规则或真实运行结果；解释性作答按评价要点由模型分析。
3. 输出每条要点是否满足、对应学生原文或运行证据、存在的矛盾，以及是否需要追问。证据不足不强行二选一。
4. 提示后完成记录为受助完成；用于独立掌握的证据需考虑题目曝光与变式关系，改题号不能清除已见答案的事实。
5. 新证据支持时可更新为“有证据支持掌握”，无需等待人工逐次审核；结论仍保留适用范围、版本和复测可能。
6. 对重要目标安排迁移或延后核验；具体题量、通过门槛与复习规则由首个教学单元的标准包确定，不在这里虚构统一数值。

### 6.4 B D I 的处理

保留相关研究维度的位置，但不擅自补写缩写定义和公式，也不直接决定通关。需要老师或原始方法资料确认含义、计算对象、原始数据和有效性后，再映射到诊断模块。没有这些依据时，学生端使用可理解的具体判断，不展示无解释的研究分数。

### 6.5 验证不能被取消人工审核的要求误解

线上不设人工审批，不等于研发不做质量评估。需要准备一组由课程内容负责人核对的参考答案、常见误解和典型学生回答，比较模型判断是否合理、是否过度判掌握、是否对提示依赖敏感。真实数据不足时可用明确标识的合成案例做工程测试，但不能据此宣称真实教学效果。

## 7 多种教学形式与 ML Lab

### 7.1 内容形式不是独立课程系统

所有形式共享目标、知识点、活动 ID、材料版本和返回位置。形式不同不意味着为学生创建另一套画像。学生可以选择现有可用材料；没有对应视频或实验时说明不可用，不显示无法兑现的入口。

| 形式 | 主要用途 | 关键记录 |
| --- | --- | --- |
| 动态讲义 | 有结构的定义、解释、推导、案例 | 段落 ID、来源、版本、笔记 |
| 对话教学 | 追问、解释、苏格拉底式引导 | 当前目标、原话、提示层级和引用 |
| 视频及课件 | 使用既有资源，补充不同表达 | 资源片段、页码或时间、返回位置 |
| 短题与辨析 | 回想、概念判断、解释与反馈 | 题目版本、回答、帮助和判据 |
| 情境任务与 Lab | 在具体问题中操作、解释、迁移 | 环境状态、参数、结果、学生解释 |
| 复习卡与个人手册 | 保存有效解释、错误修正与再学习 | 来源活动、修订历史与复测记录 |

不是所有课程都适合可执行 Lab。应先根据能力目标选择练习形态，再决定是否需要模拟、代码或实验环境；不把每个知识点强行套入五步实验。

### 7.2 现有 Lab 的价值与限制

当前 Lab 执行真实 scikit-learn 参数实验，五步主线覆盖检查数据、划分、比较、选择、封存测试。情境采用预先编写的模板，数据是明确的教学模拟数据，不能当真实业务数据。学生目前不是在自由执行任意 Python 代码。

原始基线的 `ml_api.py` 固定解析 `DEMO_ID`。当前源码已接受 `course_id`，实施记录记载了任务到课程节点的映射及回返测试；不能再把“固定演示课程”当作当前未修改事实。不过正式课程资源、React 内统一实验体验及服务端身份隔离仍需分别验证，不能仅凭参数接入宣布完整改造完成。

### 7.3 首轮改造任务

1. 保留有界实验引擎和先选配置后看测试结果的约束。
2. 把任务目标与检查合同同情境文案分离；智能体可调整解释、情境与支架，不随学生答案更改及格标准。
3. 增加任务前诊断、任务中辅导和任务后解释性评价，保留真实运行失败与认知错误的区分。
4. 补学后恢复同一实验轮次与参数；迁移任务开启新轮次，不能覆盖旧实验。
5. 普通训练不提前暴露测试分数，不允许反复看测试集后再声称独立评估。
6. 未来若支持学生自由代码，再单独建设隔离执行、资源限制与网络权限。首轮不因追求形式完整而开放宿主机执行。

## 8 多模态与数据管理

### 8.1 首轮范围

采集平台内必要操作和用户主动提交的学习内容；摄像头需单独可选授权。页面明确显示采集状态、暂停和关闭入口。后台支持按活动查找授权的视频片段及相关事件。基本线索只能触发“是否需要解释或帮助”等询问，不能直接推断心理状态，更不能作为掌握成立或不成立的充分条件。

ChatEval 可参考会话、轮次、媒体与事件组织方式；是否复制代码须另核对许可和数据权限。本指南不把参考仓库的录制能力写成 PLIAC 已具备的能力。

### 8.2 数据层次与时间对齐

1. 原始层：学习者原话、允许记录的操作、授权媒体片段及其原始时间。
2. 特征层：从原始数据提取的停顿、操作变化或可用的表情线索，记录处理版本和缺失情况。
3. 解释层：结合任务和对话形成可能困惑等假设，保留不确定性。
4. 干预层：何时询问、学生如何回应、是否改变活动，以及干预后的表现。

事件至少关联学习者、会话、活动、事件 ID、客户端时间与服务端接收时间；视频采用同一会话内的相对时间与片段编号。断连、后台标签页和设备错误单独记录，不能把缺失样本当平静或困惑。

### 8.3 真实试用前必须补齐

1. 说明采集什么、为什么采集、谁可访问、保存多久、如何撤回和删除。
2. 决定摄像头原视频是否留存、保存期限、存储位置、删除责任人与备份中的删除方式；不默认永久保存。
3. 学习用途授权与比赛展示授权分开。稳定匿名编号不能使人脸视频自动匿名。
4. 真实用户记录依靠服务端访问控制，不能仅靠知道或输入某个匿名编号就能读取。
5. 首轮不默认持续保存每个按键或完整草稿历史。确需输入修改研究时再明确采集粒度和告知范围。
6. 模型调用传输的材料、学生文本和媒体范围应清楚；不默认上传原视频到模型提供方。

这些是试用准备项，不意味着当前必须新建复杂合规系统，也不对是否依法需要特定审批作未核实结论。

## 9 前端结构与交互规范

### 9.1 技术选型

确认方向为 React＋TypeScript＋Vite＋现有 FastAPI。适合当前交互式学习工作台及前后端渐进改造；不是声称它在所有网站上性能最佳。首轮没有需要 Next.js 服务端渲染才能解决的明确需求，因此不引入第二套全栈服务。

建议 React Router 负责路由，统一设计变量负责三套主题；服务端课程与学习数据由统一 API 层管理，局部界面状态留在组件或工作台上下文。是否使用独立查询缓存库可在样板时确定，不为选型罗列大量状态工具。

### 9.2 一级页面与职责

| 页面 | 职责 | 边界 |
| --- | --- | --- |
| 学习首页 | 继续上次学习、近期目标和复习提醒 | 不重复完整课程目录 |
| 我的课程 | 课程范围、选择课程、进入学习 | 不创建平行练习系统 |
| 学习档案 | 个人教材、笔记、报告、历史成果及导出 | 不复制另一套实时学习记录 |
| 课程学习工作台 | 目标、起点、内容、互动、实践、反馈 | 从课程或续学进入，不必另设重复一级导航 |
| 管理后台 | 资料、标准、版本、证据回查和运行治理 | 与学生视图和权限分离 |

首次学习准备是工作台中的阶段，不设永久一级入口。个人地图和图谱是工作台内工具，不让学生首先面对后台资料图。档案和工作台引用同一教材对象，历史报告则保留当时快照。

### 9.3 工作台布局

左侧为可切换的课程导航，中间为主要教学内容，右侧为可收起的智能体对话。进入课程后不额外常驻一整列全局导航，避免四栏挤压。顶部保留返回课程、当前目标、保存状态、摄像头状态与必要操作。

1. 阅读时正文占主要宽度；目录与对话可收起。
2. Lab 时任务与操作获得更宽区域，保留智能体求助和返回讲义入口。
3. 集中对话时学生可主动放大对话区，当前材料及活动仍能定位。
4. 窄屏将目录和对话改为按需面板；不压缩成无法阅读的三栏。
5. 智能体负责内容、路径和活动，不因对话栏收起而停止教学主控；也不能突然覆盖正在阅读的正文。

### 9.4 跳转规则

1. 查概念、来源或掌握依据先轻量预览，关闭后回原位置；真正切换学习目标时才启动新活动。
2. 阅读到练习、Lab 到补学再返回，携带课程、活动、材料版本与返回锚点，不依赖浏览器碰巧保留的内存。
3. 课程、活动和可独立打开的成果使用稳定地址；短暂预览、菜单和主题不制造大量浏览历史。
4. 浏览器后退、刷新、直接访问链接与跨次登录需恢复一致位置；服务端校验归属，不信任 URL 中的用户编号。
5. 未发送输入、作答草稿、实验参数和最近阅读位置需要明确保存策略；界面区分正在保存、已保存、保存失败。
6. 学生正在查看历史消息时，新回复不强制滚到底；收到新内容提供轻提示。

### 9.5 阅读 翻页与活动推进

讲义小节内默认连续滚动，小节间提供上一节和下一节；PDF／课件遵循原页码，视频遵循播放时间，复习卡按题推进，Lab 按任务步骤推进。翻页不自动产生掌握结论。动态教材未生成的后续内容不伪造固定总页数。

可参考 Reader 对阅读进度与当前位置的区分：临时回看不应破坏续读位置。具体实现使用材料 ID、版本和段落锚点，内容修订后提供可解释的位置回退，而不只保存一个易失效的滚动像素值。[参考 3]

### 9.6 视觉与组件

三套主题暂以暖白阅读、中性白工具、暖深色专注命名，名称和具体色值属于设计变量。布局、路由和功能完全相同，切换不刷新、不丢实验和对话。

1. 长讲义以标题、段落、公式和插图为主，不把每段话包成卡片。
2. 卡片用于任务、资源摘要和结果，避免卡片套卡片。
3. 使用克制的边框、层级和留白；不依靠大面积渐变、发光或机器人装饰强调 AI。
4. 颜色表达状态时同时配文字或图标；考虑键盘焦点、对比度、字体放大和减少动画设置。
5. 统一组件包括工作台外框、课程导航、内容渲染器、对话面板、材料预览、活动操作区、状态提示与成果查看器。先围绕实际重复使用提取组件，不提前建设庞大低代码系统。

DeepTutor 用于借鉴视觉与持久工作台，Reader 用于借鉴正文提问，Claude 用于借鉴对话与独立成果，Linear 用于借鉴不离开当前任务的详情预览。参考产品的功能和性能不自动成为本项目已实现能力。[参考 3—6]

## 10 数据契约 接口与持久化

### 10.1 共享对象及其归属

| 对象 | 关键内容 | 归属与边界 |
| --- | --- | --- |
| CourseKnowledgeVersion | 课程知识、目标、来源与版本 | 公共课程，不随个人偏好改变 |
| LearningGoal | 范围、目标、完成要求、学生选择 | 学习者与课程 |
| LearningSession | 当前目标、活动链、恢复位置 | 学习者与课程，跨页面共享 |
| Activity | 类型、知识目标、合同、输入输出及状态 | 会话内，可关联 Lab 轮次 |
| MaterialArtifact | 内容结构、来源、版本、段落与注释 | 公共材料或个人教材须明确区分 |
| Evidence | 原始回答、操作、提示与上下文 | 不可被诊断摘要替代 |
| Diagnosis | 判据、证据引用、结论、不确定项、模型版本 | 可纠正并保留历史 |
| LearnerState | 由证据与诊断派生的知识状态 | 不能由前端直接提交为已掌握 |
| TeachingDecision | 下一动作、依据摘要、工具结果 | 用于解释和排查，不保存内部思维过程 |
| MemorySummary | 摘要、来源索引、适用范围、修订记录 | 不作为独立的新掌握证据 |
| ConsentAndMedia | 授权范围、媒体片段、时间及访问规则 | 与诊断分层，不混入普通日志 |

这些是逻辑对象，不要求首轮创建同名数据库表或独立服务。

### 10.2 接口规则

沿用现有请求标识、预期版本和课程版本机制。关键操作统一传递课程、学习会话、活动、任务版本和证据关联。API 路径在接口设计时确定，本指南不把拟新增地址描述成现有接口。

1. 重试同一提交不重复添加证据；同请求编号提交不同内容应拒绝。
2. 并发冲突保留学生草稿，刷新状态后再提交，不无提示覆盖较新状态。
3. 模型流式输出区分文本片段、工具状态、最终结果和错误。断流重连先定位任务，不把半截诊断当最终结论。
4. 页面退出和模型任务取消分别定义；离开页面不应默认丢弃已提交任务，也不允许旧任务劫持新页面。
5. 生成 HTML／Markdown、附件预览与链接必须安全处理；不能执行资料或模型嵌入的任意脚本。

### 10.3 存储选择

现有 revision 文件存储可保留作本地开发与兼容基础，不必为了新前端立即迁移数据库。但必须测试模型任务与人工操作并发时的事务行为。共享部署前根据并发和恢复需求决定是否迁移到数据库；若采用多进程服务，需确认跨进程锁与任务恢复，不能把单进程内存任务表当可靠任务队列。

备份范围除代码外，还包括受允许保存的课程配置、资料索引和学习记录。密钥分开管理，不进入仓库、前端包、导出文件或普通错误日志。

### 10.4 学习成果与导出

个人教材、笔记、有效解释和报告在线持续保存。导出以用户选择的版本为准，保留标题、公式、图表和必要来源；默认不包含摄像头原视频、后台日志和其他学生数据。Word 与 PDF 需分别检查内容完整性及版面，不把浏览器截图或一段纯文本视为完成导出功能。

## 11 搭建阶段与功能依赖

实施采用阶段成果而非僵硬的逐日排期。各阶段可以并行推进，但涉及数据契约和教学判断的依赖不能跳过。本指南不安排人员分工，直接围绕目标推进和核验。

| 阶段 | 核心任务 | 进入下一阶段的证据 |
| --- | --- | --- |
| 0 基线与契约 | 确认单元、核对规则与现有分支、备份、接口和数据样例 | 旧平台可复现，标准与核心对象可供联调 |
| 1 工作台样板 | 新前端外框、三主题、导航、阅读、活动与对话占位，接真实读取接口 | 主路径可点击、可刷新恢复；模拟内容明确标识 |
| 2 真实教学闭环 | 接真实模型、知识检索、起点判断、个性化讲解、核验、状态更新 | 两种不同起点得到有依据的不同教学，证据改变后续动作 |
| 3 实验与成果 | 解耦 Lab 课程、回到补学位置、迁移核验、个人教材及 Word／PDF | 实验与画像共用证据，成果可浏览导出且版本一致 |
| 4 多模态与真实试用 | 授权采集、时间对齐、回看、访问隔离、部署恢复与试用 | 完整拒绝授权路径及授权路径通过，真实学习过程有记录 |
| 5 修订与展示 | 根据试用改进、整理演示视频与比赛材料 | 展示内容与实测证据一致，无虚构效果和数据 |

各阶段保留必要的共同检查点：课程与评价标准能否支撑教学，前后端是否共享相同状态，教学证据是否实际改变下一步动作，保存恢复与失败路径是否可验证。常规实现不必逐项等待批准；改变已确认的范围、数据用途或教学规则时先说明并确认。

摄像头、导出与部署可在接口稳定后并行开发，不因表格顺序而机械等待全部前序工作完成。复杂微表情、任意代码沙箱、任意领域建课和大规模模型训练不作为本轮闭环的前置条件。

## 12 验收标准与证据

### 12.1 核心场景

| 编号 | 核验场景 | 通过要求 |
| --- | --- | --- |
| A01 | 新学生自评会但解释不清 | 保留自评，补充核验，不直接标掌握 |
| A02 | 两名基础不同的学生学同一知识点 | 教学顺序、解释或活动有依据的差异，不只是换称呼 |
| A03 | 学生坚持先做 Lab | 可进入并获得帮助，未核验前置仍可见 |
| A04 | 提示后答对再做迁移 | 受助与独立证据分开，旧题曝光不清零 |
| A05 | 实验结果对但解释错 | 技术完成与理解判断分别呈现 |
| A06 | 讲义到 Lab 再补学返回 | 目标、参数、草稿和返回位置保留 |
| A07 | 退出刷新与跨次续学 | 从已保存状态恢复，不重新准备全部起点 |
| A08 | 生成期间切换课程 | 旧结果不写入新课程、不覆盖新活动 |
| A09 | 重试与双标签提交 | 无重复证据；冲突可恢复草稿 |
| A10 | 模型超时或格式错误 | 明确失败、有限重试，保留内容，不伪造完成 |
| A11 | 摄像头拒绝 暂停 撤回 | 文本学习可继续，采集状态与服务端权限一致 |
| A12 | 视频与活动回看 | 能定位同一活动的片段，缺失不被当作情绪结论 |
| A13 | 其他学生尝试访问记录 | 服务端拒绝，而非仅隐藏前端按钮 |
| A14 | 教材更新与报告导出 | 版本一致，历史可查，公式图表与长内容不截断 |
| A15 | 切换三主题和窄屏 | 状态不丢、正文可读、焦点可见、图表不溢出 |
| A16 | 公共资料中含恶意指令 | 不改变权限，不泄露密钥或跨学生信息 |

### 12.2 验证层次

1. 单元和接口测试：校验结构、状态转换、幂等、权限、版本与错误处理。
2. 浏览器验证：实际操作完整主路径，覆盖后退、刷新、窄屏、主题、草稿和滚动恢复。
3. 真实模型验证：使用确实联网的模型检查来源约束、个性化、诊断与失败行为。模拟服务仅验证工程，不证明模型质量。
4. 教学质量评估：用固定参考案例检查生成覆盖、评价一致性、错误掌握判断和提示依赖。
5. 真实试用：记录完成路径、遇到的问题、前后与迁移表现、主观反馈。小样本结果如实描述，不未经设计就宣称因果提升。

流畅性需记录设备、浏览器、材料规模、网络及模型情况，分别看本地交互、页面切换、材料加载和模型首段响应。建立基线后确定性能预算，不凭动效或本地截图宣称性能最好。

### 12.3 完成定义

一个模块完成意味着：有可运行入口、实际输入输出、持久化与恢复、失败路径、自动化或可复现验证，并与其他模块联通。仅有按钮、静态页面、接口壳或模拟聊天不算完整实现。

平台首轮完成意味着：在一个正式确认的机器学习单元中，学生能经历目标协商、起点判断、个性化学习、练习或实验、证据诊断、教学调整、成果保存导出和跨次恢复；同时通过授权与拒绝摄像头两种路径，并完成受控真实试用。

## 13 开工准备评估与待确认清单

### 13.1 现在可以开始的工作

现有底座、产品主线和前端方向足以开始代码基线整理、接口设计、前端外框、状态恢复样板、模型网关与自动评价契约设计。无需等所有高级算法、所有课程资源和完整多模态研究结束后才动工。

### 13.2 正式教学联调前需要完成

1. 确认首个正式单元及一组核心知识点，避免继续用未确认章节生成大规模内容。
2. 提供可使用的课程来源和覆盖范围，至少准备目标、定义、典型误解、练习与迁移核验。
3. 制定首版评价标准包，明确什么表现支持掌握、什么只能证明受助完成、何时需要再问。
4. 确认主模型、调用预算和数据传输范围；已有 key 不等于教学质量、并发和费用已经验证。
5. 确认匿名身份如何恢复、服务端如何隔离，避免上线后任何人改编号即可读他人记录。

## 16 开工执行补充：把整体设计落实为同一条学习流程

本节为 1.2 版补充。它细化已有范围，不新增独立教师端、人工发布环节或全新课程领域。下面的组件和交互是目标契约；除明确列出的源码核对外，不代表已经完成。

### 16.1 一名学生最终怎样使用

1. 打开平台，在首页继续上次学习，或在“我的课程”选择机器学习。尚无记录时不显示虚假的掌握率或推荐效果。
2. 首次进入课程，在工作台内说明目标、基础及相关知识自评。智能体用必要的简短核验确定起点；已有足够记录的学生直接恢复，不重复填写整套表格。
3. 智能体给出当前学习安排和简短理由。学生可以接受，也可以要求先补知识或先做实验；系统保留未验证的前置状态。
4. 中央正文呈现当前小节或活动，右侧对话围绕同一目标提供帮助。选择“换个例子”修改讲解表达，不另开没有关联的课程；查看来源是临时预览，不改变学习位置。
5. 学生阅读、作答或操作实验。系统区分阅读位置、活动完成和知识判断，记录本次帮助及题面曝光；不会因为翻页或实验成功就判定掌握。
6. 智能体依据固定标准与实际证据决定下一步：继续、追问、换解释、补前置、变式练习或迁移核验。新证据可以修正旧结论，但不删除旧作答与依据。
7. 完成当前约定范围后生成阶段报告与个人教材，支持在线回看和导出。没有学完整门课也可形成成果；再次进入恢复未完成活动和学习位置。

主线可概括为：目标与状态恢复 → 选择活动 → 学习与实践 → 保存原始证据 → 按标准诊断 → 更新画像 → 调整活动。阶段成果和跨次恢复贯穿其中，不是另建两套业务流程。

### 16.2 页面与组件的明确分工

| 区域 | 放什么 | 不放什么 | 去向与恢复要求 |
| --- | --- | --- | --- |
| 首页 | 继续学习、近期目标、需要关注的复习 | 全部资料、完整诊断表 | 直接进入对应课程和活动 |
| 我的课程 | 课程范围、课程简介、进入入口 | 与工作台重复的全套学习操作 | 首次进入或恢复课程工作台 |
| 工作台顶部 | 返回、当前目标、保存及采集状态 | 多个同等级的后台链接 | 切换前保留草稿与活动位置 |
| 工作台左侧 | 章节或知识导航、当前位置 | 同时常驻全局侧栏和整张大图谱 | 预览关系不改变目标，选定学习才切换 |
| 工作台中央 | 当前讲义、问题、材料或实验 | 把全部历史消息和所有工具堆成卡片 | 活动切换后能返回原材料锚点 |
| 工作台右侧 | 当前上下文中的提问、提示与解释 | 第二套画像或另一份任务状态 | 收起不丢对话，不停止教学编排 |
| 临时预览 | 来源片段、概念关系、判断依据 | 必须跳转的新独立业务流程 | 关闭后回到原焦点与阅读位置 |
| 学习档案 | 同一份教材、笔记、报告及历史成果 | 复制出独立编辑的重复学习记录 | 打开指定版本，导出指定成果 |
| 管理后台 | 资料标准、知识版本、运行和证据回查 | 每次教学必经的审批操作 | 服务端权限独立，不靠隐藏按钮 |

组件按职责组合为：共享外框、课程导航、活动容器、内容渲染器、智能体面板、来源预览、状态提示、成果浏览器。界面不直接计算掌握或让模型返回任意页面代码。

### 16.3 智能体如何贯穿，而不是只存在于聊天框

1. 智能体主控读取同一学习会话，决定当前目标下的下一活动；对话面板只是学生与其交互的一种入口。
2. 中央内容区展示该活动的正式内容；右侧解释引用同一活动和材料版本。两者不分别创建任务或写入两份进度。
3. 触发主控的事件包括初始信息完成、学生要求调整、作答评价结束、实验完成或受阻、复测完成、跨次恢复。打字、滚动等事件不逐条触发昂贵模型调用。
4. 主控输出受限动作及目标、材料、所需工具和核验要求；服务端先检查权限、版本和数据归属，再执行。缺标准时可以讲解，但不能自动认定掌握。
5. 智能体自动调整教学无需人工审核；改变学生主动选定的较大目标时说明理由并允许选择。不得在学生输入过程中突然替换题目或清空实验。
6. 生成中展示真实状态并保留已有内容。失败提供恢复入口，不把固定模板冒充模型成功，也不让学生承担技术失败造成的负面能力判断。

### 16.7 需用户决定与可由开发处理的边界

当前最有价值的确认只有两项：首个正式教学单元是什么；第一轮验证是仅本机还是受控多人访问。前者决定内容和判据，后者决定身份与部署优先级。未决定时可以继续骨架和合成案例验证，不擅自扩大正式范围。

模型调用预算与允许的数据传输范围应在新增批量调用前确认；摄像头原视频是否保存、保存多久、谁删除应在真实采集前确认；比赛日期与提交要求应在安排展示交付前核实。它们不必全部阻塞前端与契约开发。

## 17 目标范围与开工确认补充

本节为 1.3 版补充。此次实际检查了当前分支、未提交文件清单、仓库约束、前端依赖、后端入口及既有实施记录；没有重新运行测试、浏览器或付费模型，没有提交、推送或修改业务代码。此前测试记录仍属于对应批次，不能替代当前工作区验收。

### 17.1 从学生目标到可执行学习范围

1. 学生选择系统学习、补知识点或完成某类任务，并说明目标；教学形式偏好另行记录，不把“喜欢 Lab”当作学习目标或能力结论。
2. 智能体根据当前可用课程知识、来源、任务标准及学生状态，提出学习范围、建议顺序、起点和理由。系统学习指明覆盖的是当前可用课程范围，不能把不完整的课程图包装成完整学科。
3. 目标超出机器学习课程、所需资源缺失或任务含义不清时先澄清，不编造知识点、实验或评价标准。暂不可核验的部分可以提供有依据的学习帮助，但不得判掌握。
4. 学生可采用或调整范围，也可坚持先学某点、先做可用实验。学生采用自己的学习计划不是人工教学审核；后续日常讲解、练习和诊断仍由智能体自动推进。
5. 区分目标知识和辅助先修。补前置知识是为了完成原目标，不悄悄把一个小目标扩展成整门课程；需要明显扩大范围时说明原因，让学生选择。
6. 保存计划版本及所用课程版本。修改目标不删除旧教材、作答或诊断；生成中的旧计划不得覆盖新目标。课程更新后检查旧计划适用性，不能默默把不同版本的判据混用。
7. 按计划推进不等于掌握：阅读结束、走完步骤、完成实验与证据支持目标达成分别记录。只有相应标准和证据支持时，才形成该范围内的掌握结论；学生提前结束也能保存成果，但报告应保留尚未核验部分。
8. 完成约定范围后形成阶段成果，并允许继续新目标或复习。跨次进入恢复原计划和未完成活动，不每次从头生成一份新计划。
