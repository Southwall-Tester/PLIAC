# 星萤 Starglow 平台架构说明（2026-10-10，交接给 Codex）

本文是**当前架构的权威说明**：功能板块、板块之间的逻辑、学生的学习逻辑、前端结构，以及以后要改细节时应该改哪里。

- 设计与实现对照：`design-vs-implementation-20261010.md`
- 专题复盘：`architecture-review-20261010.md`

## 0 结论：架构是否符合要求、能否支撑后续灵活调整

**符合。** “智能体全程驱动”的骨架已经在服务端成形，具体落在以下几处：
- 共享知识框架（课程图谱）；
- 个人状态分三层：证据 → 诊断 → 状态；
- 教学主控：由触发事件驱动，智能体给出带理由的下一步；
- 多种学习活动：都写回同一份证据。

**能支撑灵活调整。** 主要扩展点都是“登记即可”的形式，见第 6 节：
- 新的学习形式；
- 新资源；
- 新课程；
- 新的诊断信号；
- 更换模型。

需要注意的结构性短板见第 8 节，最重要的三条是：
1. 前端 `WorkspacePage` 承担太多职责；
2. 新旧两条推进路径并存：智能体主控 vs 旧版“让智能体安排下一步”；
3. 讲义概念与课程框架没有统一 ID。

这三条不影响继续开发，但应在加新功能前顺手收敛。

## 1 总体结构

```
┌──────────────────────────────── 前端 web/（React + TS + Vite，/app/）────────────────────────────────┐
│ 首页（目标）  我的课程  学习档案  账户 │ 课程学习工作台（目录/星图 · 活动区 · 教学对话 · 抽屉）│ /admin/*（管理端）│
└───────────────────────────────────────────────┬───────────────────────────────────────────────────────┘
                                                │ JSON API（/api/*）
┌───────────────────────────────── 后端 src/（FastAPI 模块化单体）─────────────────────────────────────┐
│ 接入层      access（匿名身份/管理员） api 路由（learning / tutor / handouts / ml-lab / media / courses）│
│ 智能体运行层 teaching_flow（主控触发） tutor（讲解/对话/下一步提案） learning_plan（范围规划）        │
│             knowledge_activation（自动核验） margin/margin_graph（资料→讲义与概念图）               │
│ 活动服务层  workspace（逐节学习/作答/标注） assessment（检验） ml_lab（实验） study（提取练习）      │
│             resources + resource_catalog（材料推荐） notebook（笔记） reports（报告）               │
│ 学习者层    course_graph.learner（证据→诊断→状态）  memory（记忆投影）  review_reminders/rhythm   │
│ 知识资源层  course_graph / course_catalog / acceptance_course（课程框架） documents/retrieval（来源）│
│ 观察层      media / media_timeline（授权录像、时间线、复核）                                         │
│ 存储        outputs/ 下 JSON 文件；原始证据、诊断、派生状态分开保存；带版本与幂等请求号             │
└──────────────────────────────────────────────────────────────────────────────────────────────────────┘
外部：千问（统一由 configured_api() 读取配置；不要读取或打印 config/models.json）
```

`src/learning_agent` 负责“知识、资产、证据与诊断”；`src/pliac` 负责“学习工作台与编排”（AGENTS.md）。

## 2 功能板块与职责

### 2.1 知识与资源层（课程侧，所有学生共享）

| 板块 | 文件 | 职责 | 不负责 |
|---|---|---|---|
| 课程框架 | `learning_agent/course_graph.py`、`course_catalog.py`、`acceptance_course.py` | 章节、知识点、关系（先修/相关/易混）、讲解内容、题目、复习间隔策略；课程版本 | 学生个人内容 |
| 概念层 | `data/acceptance_concepts.json` → `/api/learning` 的 `concept_map` | 示范课 30 个概念、44 条边，与知识点关联 | — |
| 来源资料 | `documents.py`、`source_reading.py`、`retrieval.py` | 教材/PDF 按页按段落取用、检索，回答与讲解的依据 | 生成结论 |
| 讲义与资料概念图 | `margin.py`、`margin_graph.py`（LearnMargin，concept-first-v3） | 从课程资料生成课程讲义与概念图（课程级，每门课一份） | 个人化改写（应由智能体在其上完成） |
| 自动核验 | `knowledge_activation.py` | 候选知识经来源和结构核验后生效，候选版与可用版分开 | 伪造人工审核 |
| 资源 | `resources.py`、`resource_catalog.py`、`data/resource_catalog/*.json` | 视频/图文/案例按知识点推荐，说明与当前缺口的关系 | 判断掌握 |
| 实验合同 | `ml_contract.py`、`ml_engine.py` | 参数化实验任务、判定规则 | — |

### 2.2 学习者层（个人，随证据变化）

三层数据，不能互相替代：

| 层 | 内容 | 写入者 |
|---|---|---|
| 原始证据 | 作答原文、标注、对话、实验操作、提示等级、曝光 | 活动服务 |
| 诊断 | 对证据的判断、依据、不确定项、规则或模型版本 | assessment / 规则 |
| 派生状态 | 节点状态（已掌握/待核验/需补学/未学）、到期复习、画像、记忆 | `course_graph` 统一计算 |

- 记忆（`memory.py`）只是证据的投影，**不产生新诊断**。
- 笔记（`notebook.py`）不是掌握证据。
- 活动进度（读完、打开材料）**不能**推出掌握。

### 2.3 智能体运行层

| 角色 | 文件 | 输入 → 输出 |
|---|---|---|
| 教学主控 | `teaching_flow.py` + `tutor.py`（advance） | 触发事件 + 状态 + 计划 → **提案**：目标知识点、活动类型、理由，并生成学习材料 |
| 范围规划 | `learning_plan.py` | 目标 + 起点 → 学习范围（学生采用后生效） |
| 对话教学 | `tutor.py`、`tutor_api.py` | 问题 + 上下文（知识点、来源、证据、资源）→ 受控回答（讲解阶段完整，检验阶段限答） |
| 讲义生成 | `margin.py` | 课程资料 → 讲义、概念图 |
| 知识核验 | `knowledge_activation.py` | 候选知识 → 核验报告 → 可用版本 |

主控的触发事件（`teaching_flow`）：

| 触发 | 含义 |
|---|---|
| `initial_diagnosis` | 首次确认起点 |
| `goal_changed` | 学习目标变了 |
| `plan_accepted` | 学生采用了学习范围 |
| `assessment_evaluated` | 检验有了结果 |
| `reading_finished` | 读完当前材料 |
| `lab_finished` | 实验结束 |
| `student_choice` | 学生从目录或星图指定知识点 |

每次决策都保存目标、引用证据、动作类型、理由和模型版本（build-guide 5.2）。学生可以暂停或恢复主控，也可以自己选知识点。

### 2.4 活动服务层（学生实际做的事）

| 活动 | 后端 | 前端 | 产出证据 |
|---|---|---|---|
| 讲解（智能体材料/小节） | `workspace.next_lesson`、`tutor` | 讲解标签、`TeachingMaterial` | 阅读、标注、追问 |
| 课程讲义 | `margin` | 讲义标签、`Handouts` | 阅读位置 |
| 视频与资料 | `resources` | 视频与资料标签、`MaterialList` | 资源使用记录（`/resource-use`） |
| 检验 | `assessment` | 检验标签、`AssessmentPanel` | 作答、提示等级、判定 |
| 实验 | `ml_lab` | 实验标签、`MLLab` | 运行记录、检查结果、提示等级 |
| 对话 | `tutor_api` | 右侧 `TutorPanel` | 问题与回答 |
| 笔记 / 进度 / 报告 / 手册 | `notebook`、`workspace.chapter_reports/handbook`、`reports` | 抽屉、学习档案 | 不是掌握证据 |

### 2.5 观察层（多模态）

`media*.py` + `CameraPanel`：授权后录像，按活动对齐时间线，管理端回看（`/admin/media-review`）。

目前**只记录、不进入决策**。接入的位置预留在：主控上下文装配（`tutor.teaching_context`）+ 新的辅助证据类型（见 6.4）。

## 3 板块之间的逻辑（一次完整的数据流）

```
学生动作（读/答/做/问/标注）
   │ POST /api/learning/* 或 /api/tutor/* 或 /api/ml-lab
   ▼
活动服务：校验 → 写原始证据（带 expected_version 与 request_id，防重复、防覆盖）
   ▼
诊断：规则判定（示范课 demo-choice-v1）或评价服务 → 诊断记录（含依据、不确定项）
   ▼
学习者层：重算节点状态 / 到期复习 / 记忆投影
   ▼
teaching_flow：产生触发（如 assessment_evaluated）
   ▼
智能体主控：读 上下文（目标、计划、子图、状态、证据、资源）→ 提案（下一节点 + 活动 + 理由）→ 生成材料
   ▼
前端：/api/learning 返回新的 Workspace；PathBar、GuidedFlow、目录与星图颜色随之更新
```

关键约束：
- 只有先修边约束学习顺序；
- 技术失败不算能力不足；
- 模型输出要通过服务端校验后才写入；
- 资料和学生输入都只是数据，不当作指令。

## 4 学生的学习逻辑

### 4.1 主线

```
首页说目标 ─→ 选/进课程 ─→ 起点（少量自评 + 必要核验）─→ 智能体规划范围 ─→ 学生采用
   ─→【知识点循环】─→ 章末报告 ─→ 补学复测 / 下一章 ─→ 间隔复习（跨次）
          ↑                                                  │
          └──────────── 中断后再次进入：恢复位置与草稿，仅核验过时状态 ┘
```

### 4.2 知识点循环（一个节点内）

```
  讲解（可选：讲义 / 视频与资料 / 对话追问）
     ↓ 读完
  检验（分级提示，记录提示等级）
     ↓ 判定
  ├─ 证据支持掌握 ─→ 下一个知识点（或安排实验做迁移）
  ├─ 待核验 ───────→ 换一道题 / 换情境再检验
  └─ 需补学 ───────→ 智能体换讲法、补前置知识 ─→ 再检验
```

- 实验放在讲解之后，既是巩固也是检验（v7 2.3）。
- 页面上，学生在**路径条**（PathBar）看到：本章位置、当前状态、一条下一步建议。
- 智能体的详细安排和理由在 **GuidedFlow**（“智能体安排”）里。

### 4.3 状态显示约定

| 状态 | 颜色 | 依据 |
|---|---|---|
| 已掌握 | 萤光金 | 证据支持掌握 |
| 待核验 | 蓝 | 证据不足或冲突 |
| 需补学 | 红 | 检验暴露缺口 |
| 未学 | 空心 | 没有证据 |
| 复习到期 | 标签“复习到期” | 间隔规则 |

## 5 前端结构

### 5.1 路由（`web/src/main.tsx`）

| 地址 | 页面 | 说明 |
|---|---|---|
| `/app/` | 首页 | 说目标、继续学习、复习提醒 |
| `/app/courses` | 我的课程 | 可学 / 准备中 |
| `/app/courses/:courseId` | 课程学习工作台 | 不显示全局导航 |
| `/app/archive` | 学习档案 | 讲义、笔记、报告、导出 |
| `/app/account` | 账户 | 匿名编号、恢复码、管理员入口 |
| `/app/admin/media-review`、`/admin/job-recovery`、`/admin/knowledge-activation` | 管理端 | **本轮从学生路由中分出**，旧地址自动跳转 |

### 5.2 工作台的 URL 状态（刷新、后退、分享都能恢复）

| 参数 | 含义 |
|---|---|
| `?node=` | 当前知识点 |
| `?view=handout\|materials\|check`、`?lab=1` | 当前活动，由 `activities.ts` 统一解析 |
| `?material=` | 智能体生成的某份材料 |
| `?lesson=` | 历史小节 |
| `?report=` | 阶段报告 |
| `?setup=1&goal=` | 目标与起点 |
| `?resource=` | 定位到某个推荐资源（进入“视频与资料”活动） |

服务端数据统一通过 `/api/learning` 返回 `Workspace`。只属于本机的状态（主题、目录或星图模式、对话栏开关、滚动位置、草稿）放在 localStorage，键名带学习者编号。

### 5.3 工作台布局

```
┌ 顶栏：返回 · 目录开关 · 课程/知识点 ·······（关系）笔记 学习进度 目标与起点 主题 对话 ┐
├ 左：目录 | 星图 ┬ 中：活动标签 讲解 讲义 视频与资料 检验 实验 ┬ 右：教学对话（可收起）┤
│ （星图可全屏）  │ 路径条：本章 ●●○○○ 3/5 · 待核验 · 下一步[去检验]│ 建议问题 / 输入框      │
│                 │ 学习范围（LearningPlanPanel）/ 智能体安排     │                        │
│                 │ 当前活动内容                                  │                        │
└─────────────────┴───────────────────────────────────────────────┴────────────────────────┘
抽屉：笔记 / 学习进度（章节进度 + 学习记忆 + 阶段报告）
```

### 5.4 本轮前端评估与调整

| 问题 | 评估 | 本轮处理 |
|---|---|---|
| 同一件事三个入口：活动标签、“这一节可以这样学”卡片、顶栏“材料” | 学生分不清该点哪里；也不利于以后加新形式 | 合并为**一套活动标签**（`activities.ts` 注册表）；“视频与资料”成为页内活动，删除卡片区与顶栏材料按钮 |
| 学生看不到“我在哪、下一步做什么” | 后台逻辑清楚，前台不清楚 | 新增 **PathBar**：本章节点点阵（可点击）、已掌握数、当前状态、一条下一步建议与按钮 |
| 管理端页面挂在学生路由下 | 违反 build-guide 9.2 的“与学生视图分开” | 移到 `/admin/*`，旧地址自动跳转，测试已改 |
| 资料只能在弹窗里看 | 视频适合在主区域看 | `MaterialList` 抽成组件，主区域和深链弹窗共用；按形式筛选（视频/图文/案例） |
| “设置起点”提示与路径条重复 | — | 去掉正文里的提示条，由路径条承担 |

### 5.5 前端仍需改进（建议 Codex 处理）

1. **拆分 `WorkspacePage`**（`main.tsx` 约 240 行，状态和渲染混在一起）：
   - 拆出 `useWorkspaceRoute()`（解析 URL：node / activity / material / lesson / report）；
   - 拆出 `WorkspaceTopBar`；
   - 拆出 `ActivityOutlet`，按 `ActivityKey` 映射渲染器。
   - 加新活动时只改 `activities.ts` 与 renderers。
2. **统一“下一步”**：
   - 现在有三处：PathBar 下一步（规则）、GuidedFlow 提案（智能体）、正文底部“读完了？”。
   - 目标是 PathBar 优先显示智能体提案（`tutor_turns` 当前 turn 的 `rationale`），没有提案时退回规则；底部只保留“去检验”。
3. **顶栏精简**：“笔记 / 学习进度 / 目标与起点 / 主题”收进一个“更多”菜单，顶栏只留 关系、对话、更多。
4. **类型补全**：`api.ts` 的 `Workspace` 缺 `rhythm`、`handbook`、`due` 等字段，目前靠 `as` 强转。
5. **标注入口**：讲解正文划词 → “标为不懂” → 调用后端已有的 `workspace.annotate`。按“标黄 → 逐条解读”设计（v7 2.2）。
6. **移动端**：窄屏时路径条换行可用，但星图全屏与对话面板需要再测一次。

## 6 扩展点：以后调整细节时改哪里

| 想做的事 | 改哪里 | 不需要动 |
|---|---|---|
| **新增学习形式**（交互模拟、情境任务、复习卡、OpenMAIC 式“场景”） | 前端 `activities.ts` 登记 + 渲染器；后端新增活动服务，写证据时用统一的 `_evidence(…, source=新类型)` | 诊断与状态计算、主控 |
| 让智能体能安排这种形式 | `tutor.py` 提案的 `action`/`activity.type` 枚举 + 提示词 | 前端路由（已按活动类型打开） |
| **加资源**（视频、文档） | `data/resource_catalog/<course_id>.json`（字段格式见 architecture-review 第 1 节） | 代码 |
| **加课程** | `course_catalog` 注册 + 课程包（`course_package.py`）+ 资料走 handouts/activation | 前端 |
| 换模型、改提示词 | `llm.py`、`configured_api()`；各模块的 prompt 常量 | 业务流程 |
| **新的诊断信号**（输入删改、停顿、多模态） | 新证据类型（标为辅助）→ 由 `tutor.teaching_context` 装配给主控；**不**进掌握计算 | 状态规则 |
| 改复习间隔 | 课程 `review_policy.intervals_days` | 代码 |
| 改学习顺序策略 | `workspace._choose_node`（只认先修边）；课程可选的 `learning_order` | 图谱数据 |
| 改图谱外观 | `GraphCanvas.tsx`（`toEngine` 主题、布局参数）、`StarMap.tsx`（卡片） | 引擎 `static/network-*.js` |
| 改讲义生成 | `margin.py` / `margin_graph.py`（流水线修，不手改单张图） | 前端 |

## 7 与参考项目的对应（可直接复用的部分）

两个项目的许可都允许复用代码，复用时保留版权声明，并记录在 `docs/third-party/`。

### 7.1 OpenMAIC（MIT）

| 可复用 | 落点 |
|---|---|
| “大纲 → 场景”两段生成 | 对应“学习计划 → 逐节材料”，场景类型即第 6 节的“新增学习形式” |
| 交互式 HTML 模拟 | 新活动 `simulation`，内容需用受限渲染器或沙箱 iframe（build-guide 5.2：不执行模型直接输出的任意脚本） |

### 7.2 DeepTutor（Apache-2.0，本地 `../DeepTutor`）

| 可复用 | 落点 |
|---|---|
| 沉浸式视频（字幕检索、按时间提问） | “视频与资料”活动 |
| 沉浸式阅读的划词操作 | 标注入口 |
| 三层记忆可视化 | 学习进度抽屉 |
| Mastery Path 的掌握门槛 | 章末达标检查 |

### 7.3 规则

只搬与本项目学习闭环相关的部分：
- 不引入社区、IM 伙伴、多引擎 RAG；
- 不引入第二套前端框架。OpenMAIC 用的是 Next.js，只能参考其组件和交互，再用 React + Vite 重写。

## 8 结构性短板与技术债（按优先级）

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | 两条推进路径并存：`teaching_flow.enabled` 为假时走旧 `TeachingAdvance` | 两套逻辑要同时维护 | 新学习者默认启用主控；旧路径只保留给示范课的验收记录 |
| 2 | `WorkspacePage` 过大 | 加功能时容易互相影响 | 按 5.5-1 拆分 |
| 3 | 讲义概念与课程知识点只按名称对齐 | 讲义里的证据没法回到节点状态 | 在 `margin_graph` 产物里写入 `node_id` 映射（自动对齐 + 核验） |
| 4 | 课程讲义不个人化 | 千人千面只体现在智能体讲解 | 智能体以课程讲义为素材生成个人版（跳过已掌握、换案例） |
| 5 | 多模态未进入决策 | 观察—判断—调整的闭环缺一环 | 先记录过程线索，作为辅助信号给主控 |
| 6 | 错误类型库、实训骨架只有实验合同里的一部分 | 无法“错误归因到知识点” | 按 v7 3.2 建课程侧条目（JSON 即可） |
| 7 | 存储是 JSON 文件 | 单机试用足够；多人并发要上 SQLite | 字段已按 build-guide 第 10 节定义，迁移时不改语义 |
| 8 | 旧静态页面（`/static`、`/learn` 等）仍在 | 两套界面入口 | 新流程完全由 `/app/` 定义；旧入口逐步下线 |

## 9 接手顺序建议（Codex）

1. 读本文 + `handoff-to-chatgpt-20261010.md` + AGENTS.md。
2. 跑测试（命令见交接文档），启动服务（`.claude/launch.json` 中的 `pliac-workspace`，端口 8020）。
3. 先做结构收敛：8-1（统一推进路径）、5.5-1（拆 WorkspacePage）、5.5-2（统一下一步）。
4. 再做功能：
   - 标注 → 逐条解读；
   - 节点后安排实验或检验、章末达标分支；
   - 过程线索；
   - 交互模拟（借鉴 OpenMAIC）；
   - 视频字幕与时间点（借鉴 DeepTutor）。
5. 每完成一项，更新 `design-vs-implementation-20261010.md` 对应行。
