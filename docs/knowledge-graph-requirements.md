# 知识图谱需求与原图谱评估（2026-10-10）

依据：启动指导会纪要（知识图谱为实体—关系有向图、体现前后继学习顺序、绿/红显示掌握、演示 30–40 节点、大模型生成后人工校验）、10 月 4 日讨论会、`docs/build-guide-20261009.md` 第 4、9 章、平台搭建框架 v3 第 5.2 节、`AGENTS.md`。

## 0 图谱在平台中的定位（依据平台搭建框架 v3“智能体全程驱动”与老师设想）

一门核心课程的教材和资料多种多样，但提炼出来的知识点和关系是同一套、相对不变的框架。**知识图谱就是这套框架**，智能体依据它为基础和偏好不同的学生生成千人千面的教材，并在练习、对话和多模态观察中持续判断与调整。图谱因此有三层用途：

1. **智能体的教学骨架**：先修关系决定先教什么、缺什么补什么；节点挂来源，是生成个人教材的依据；作答与过程证据落在节点上，智能体据此判断掌握、安排复习。
2. **学生的认知地图**：我在哪、哪些已点亮、下一步去哪、为什么先学这个；可在图上自主选路，并从任一节点发起“让智能体围绕它安排学习”。
3. **课程的共同框架**：由智能体从多份资料提炼候选，经自动来源与结构核验成为可用版本，再按教学中暴露的缺口迭代；不是人工发布后定死。

## 1 我们对图谱的要求

### 1.1 数据与语义
1. 知识点有稳定 ID、名称、定义、来源引用和版本。
2. 关系分清类型：只有经验证的**先修**约束学习顺序；相关、易混、包含、共现都不能冒充先修。
3. 概念和关系都能**回溯到原文**（页码或段落）。
4. 区分**候选**与**可用**版本：学生学习只用可用版本；候选图（例如资料抽取的共现图）必须明确标注。
5. 建构流程：资料解析 → 保留出处 → 候选概念抽取 → 归一/消歧 → 关系抽取 → 结构与语义检查 → 可用版本 → 按缺口迭代。

### 1.2 学生端呈现
6. 默认显示与**当前知识点或目标相关的局部图**，可切换到课程全景。
7. 叠加**个人学习状态**（已掌握 / 待核验 / 需补学 / 未学），且不只靠颜色区分（要有文字或图例）。
8. 点一个点能看到：关系、掌握依据、相关学习材料、**下一步动作**（例如“去学这一节”）。
9. 与目录、学习内容联动：当前位置高亮，点击能跳转。
10. 不把后台资料大图直接丢给学生；图谱是工作台里的工具，不是首页。

### 1.3 规模与交互
11. 课程级 10–40 个点要清晰；讲义/整书级 100–500 个点、上千条关系也要能用：**缩放、平移、聚焦、筛选**。

### 1.4 作者/管理端
12. 编辑知识点和关系、导入书籍、整理布局、筛选、统计。属于管理端，不进学生端。

### 1.5 风格
13. 与“星萤”品牌一致（星图视觉、掌握点萤火发光）。

## 2 逐项评估

原图谱 = `static/network-view.js` + `network-pixi.js`（PixiJS GPU 渲染）+ `network-layout.js`，用于 `/learn` 概念图、`/author` 编辑图、讲义阅读器。新星图 = `web/src/StarMap.tsx`（SVG）。

| # | 要求 | 原图谱 | 新星图 |
|---|---|---|---|
| 1–3 | 数据、关系类型、来源回溯 | 符合（`/learn` 概念面板有关系谓词和来源链接） | 符合（同一份数据） |
| 4 | 候选/可用区分 | 符合（草稿标“草稿 v1”，讲义图标注候选） | 符合 |
| 5 | 建构流程 | 有（`/author` + 文档抽取管线） | 不涉及 |
| 6 | 局部图 + 全景 | 仅全图 | **符合**（两跳邻域 + 全景） |
| 7 | 个人状态叠加 | `/learn` 有掌握着色与“当前小节”着色模式 | 符合（萤火发光 + 图例） |
| 8 | 点节点看依据和动作 | **更完整**：概念、相关小节、关系、来源，还有“确认学习起点” | 概念、相关小节、关系、来源；**缺掌握依据和下一步动作** |
| 9 | 与目录/内容联动 | 符合 | 符合 |

| 13 | 品牌风格 | 浅色画布，未统一 | 符合 |

## 3 结论

原图谱在**规模、交互和作者工具**上明显更强；`/learn` 的概念面板设计本身就符合需求，不是“不适合”。新星图在**局部视图、个人状态叠加、品牌和与新工作台融合**上更好，但渲染能力撑不起讲义级和整书级大图。

## 4 方案（2026-10-10 用户确认：复用原引擎 + 星图主题）

1. **一个引擎**：复用原 `NetworkView`（GPU、缩放、聚焦）作为工作台图谱的渲染引擎，在 React 中挂载，套用星图主题（夜空底色、萤火色掌握点、状态图例）。局部图、全景、讲义大图都用它。
2. 现有 SVG 星图只保留在**首页小星图**（小、无交互需求）。
3. 节点卡补齐原 `/learn` 已有、新版缺少的部分：**掌握依据**、**去学这一节 / 设为学习起点**。
4. 作者工具继续使用原 `/author`，在管理入口提供链接，不搬进学生端。
5. 数据层不变；先修/共现区分、候选标注、来源回溯沿用现有实现。

## 5 实施情况（2026-10-10）

1. `web/src/GraphCanvas.tsx`：按需加载 `/static/vendor/pixi-8.19.0.min.js`、`network-layout.js`、`graph-encoding.js`、`network-pixi.js`、`network-view.js`，挂载原 `NetworkView`；数据翻译为星图主题（夜空画布、分组色、已掌握 `shadowBlur` 萤火光晕、待核验蓝色光晕、需补学珊瑚色、当前点白色描边、先修/有向箭头、相关/共现虚线）；提供适应画布、放大、缩小；引擎原有拖拽、滚轮缩放、悬停聚焦高亮保留。少于 15 点时收紧布局并放大标签。
2. 工作台左栏星图（局部）、全景星图、讲义知识图均改用该引擎；首页小星图仍用 SVG（无交互需求）。
3. 节点卡片补齐：每个相关小节的**掌握依据**（学习者状态 reason）、**去学这一节**、**让智能体围绕它安排学习**（调用 `/api/tutor/flow` 的 `choose`，未设置起点时先进入起点设置并预填目标）。无概念图谱的课程显示小节卡片：掌握依据、先修、学完可接着学、相关与易混。
4. 实测：示范课 30 概念全景清晰可交互；全书大图 500 点 / 2000 边可显示、缩放；真实鼠标点击节点弹出卡片。
5. 未完成：全书大图初始视图偏小（需缩放查看），原讲义阅读器的章节层级布局（`document-subgraphs.js`）尚未接入；作者端仍使用原 `/author`；正式课图谱待自动核验通过后对学生可见。
