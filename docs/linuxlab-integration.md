# LinuxLab 与课程知识图谱

从课程管理中打开 Linux 课程的“LinuxLab · 九关实训”。课程尚未发布时可以草稿试跑；
正式学习使用经过审核发布的课程。学习者在本机真实 Linux / WSL 终端中操作，网页负责知识导航、
周目管理、证据同步、解释提交和诊断展示。没有浏览器任意命令执行 API，也没有改写 LinuxLab 的判题规则。

## 保留的核心与课程调整

### 持久图谱与学习反馈

课程的已发布图谱 `published/v<版本>.json` 是学习与实训反馈的固定依据，保存稳定的知识点 ID。
打开页面、刷新、同步 LinuxLab 记录都只读取该图谱；变更课程内容须显式保存并发布新版本，旧版本保留。
每个实训周目额外冻结 `graph.json`，并绑定课程 ID、版本和学习者编号。
证据、诊断和派生掌握状态保存在学习者记录中，以知识点 ID 关联图谱；它们不改写图谱结构。
LinuxLab、课程练习与图谱页共用按课程保存的学习者编号，实训跳转同时显式传递该编号。

LearnMargin 的 `handouts/jobs/<任务>/knowledge-map.json` 是某份 AI 讲义的概念图，
不替代课程图谱，也不能直接承接课程节点的掌握状态。生成 AI 讲义不属于查看课程图谱或同步实训的步骤。
LinuxLab 自动同步保留原始检查证据和 `uncertain` 诊断草稿，另提供逐知识点的实训掌握估计，
叠加在持久课程图谱上；自动等级与人工确认分开。规则、过程信号与版本策略见 [自动反馈设计](linuxlab-mastery.md)。

## 怎样产生有依据的诊断

1. **记录可观察事实。** LinuxLab 的检查器产生结果事件；Bash 提示符钩子产生有限操作观察。
   白名单包括命令类别、允许的选项、对象角色、退出码、有限文件结构事实、输入问题类别、尝试段和修正记录。
   不复制存档参考答案、完整 Shell 命令、原生 stderr、按键或 Vim 内部过程。主动答疑的文字另按下面的对话通路保存。
2. **冻结语境。** 周目绑定课程 ID/版本、匿名学习者、草稿或正式模式、任务合同版本及哈希、关卡映射。
   新周目保留旧周目；续学不换绑。合同漂移阻止新启动。原始白名单报告按内容哈希保存。
3. **关联知识。** 检查类别和具体输入类别映射到 Lab 概念，再映射到课程节点；阶段映射提供任务语境。
   只有先修边被列为排查候选，相关/易混淆边不当作学习顺序，也不据此批量判定知识缺陷。
4. **提出可反驳的解释。** 规则先列事实，再列多个可能原因，并附该节点的核验题。
   同阶段、上次检查/恢复后的相邻操作可加强具体候选解释；别名、函数、组合命令不套用普通命令语义。
5. **保留反证与帮助语境。** 同一现场重复检查只计一个问题段；后续通过记为检查项已修正。
   提示/助教等级随记录保存；学习者解释不得把已观察的帮助改为零提示。
6. **分别保存。** 原始报告、技术证据、学习者原话、诊断草稿与派生学习状态分开。
   正式课程同步到同一个 CourseGraphStore 学习者存储，重复同步不重复创建证据。
   自动诊断状态为 `uncertain` / `draft`，不制造人工审核或掌握结论。
7. **核验后复核。** 学习者解释可以供教师对照现场判断；需要时进行换数据的独立复测。
   已发布课程使用现有“教学复核”入口，引用任务绑定证据、填写依据和真实复核人。
   现有规则仍拒绝仅以技术事件标记“掌握”或“需要补学”。

例：复制后出现额外目录层级。系统引用 `cp` 操作后的结构观察及失败检查，关联 `cp`、隐藏项和副本完整性，
提出“目标已存在时复制目录本身”这一候选，同时保留后续移动的可能；让学习者解释源/目标语义并核验。
后续检查通过只说明现场已满足要求，不能单凭这一点断言先前原因或独立掌握。

“合格诊断”的工程门槛是：证据可定位、知识映射有效、事实与假设分离、有替代解释、有核验问题、
保留提示等级和数据缺口、不越过证据推断掌握。页面逐项展示这些条件。
该门槛保证可审查性，不等同于经过真实课堂数据验证的诊断准确率；目前没有此类效果验证。

## 本机部署

### 对话辅助诊断

`lab chat` 现在在同一次模型请求中取得答疑文字及对当前学习者原话的候选分析。每个候选必须引用本次原话中的连续片段，并使用已知概念或命令标识；无法核对的候选丢弃，改用明确标注的本地词项关联，保留可用的答疑文字。断网时同样可以记录原话与本地资料，不能冒充模型分析。

本地交换报告增加独立的 `dialogue_evidence`、`dialogue_analysis` 和 `dialogue_total`。原始记录区分学习者文字与助教回复，另保留提问时、回复交付时的操作序号和事件游标。每轮分析标记 `unverified` 及来源、策略版本；不是经审核的诊断结论。平台只依据冻结图谱映射已有节点，不生成图谱或调用新模型。

诊断策略 `linuxlab-evidence-diagnosis-v3` 把这些原话关联到最近的相关检查问题，展示讲解内容，并对照回复交付后的操作与检查：仍有失败、相关成功操作后通过、仅检查通过、发生现场恢复、尚无后续观察。等待网络回复期间的操作不算收到帮助后的表现；之后的其他提示也会注明。先后关系不证明因果，讲解本身也可能错误。提问次数不算知识错误次数，学习者粘贴的报错仍是自述，不冒充已采集的 stderr。

网页增加“答疑对话与帮助背景”，诊断条目显示学习者原话、AI/本地资料、候选引用、图谱链接和核验问题。重复 AI 文字的可观察重合会标记，但不推断复制意图。发布课程的共享学习者存储保存原话为 `learner_expression` / `annotation`，模型回复保存为 `model_inference` / `technical`；自动诊断仍为 `uncertain` / `draft`。聊天不被冒充为完成核验题的独立作答。

仅保留最近一百轮对话及候选；已同步的原始快照不可变，重复同步不重复导入，旧报告缺少对话字段仍兼容。旧版聊天缺少这些操作游标，不自动补推过去的因果关系。`/clear` 只切换后续对话上下文，不删除已发生的帮助；`lab tracking off` 不关闭主动答疑记录。模型候选的语义正确性、真实学习增益尚未得到课堂验证。

默认查找当前用户桌面的 `LinuxLab`，Windows 使用 WSL `Ubuntu`；可在启动 PLIAC 前设置：

```powershell
$env:PLIAC_LINUXLAB_ROOT = 'C:\Users\HP\Desktop\LinuxLab'
$env:PLIAC_LINUXLAB_DISTRO = 'Ubuntu'
```

LinuxLab 源码/学生包需包含 `pliac_bridge.py`。平台通过其 `--describe` 输出核对任务合同。
网页创建周目后可打开独立终端，也可复制生成的启动命令。启动只接受本机、同源请求；
此本地研究平台的匿名编号不是用户认证，交换文件也不是防作弊签名。

PLIAC 的运行数据位于 `outputs/course_graph/courses/<课程编号>/linuxlab/runs/<绑定编号>/`：
`binding.json`、冻结 `graph.json`/`descriptor.json`、`telemetry.json`、`raw/<哈希>.json`、`import.json`、`reflections.json`。
真实操作文件与检查点放在 Linux 文件系统 `~/.local/share/pliac-linuxlab/<绑定编号>`，保障原生 chmod 语义；
不改普通 LinuxLab 的 `~/.local/share/orbit-lab`。
关闭过程采集使用原有 `lab tracking off`；已有记录和检查结果保留。采集有容量上限，报告明确展示缺失范围。
本地交换不新增网络发送；原有 AI 助教仅按 LinuxLab 配置及显式使用方式工作。

首次安装运行 `scripts/install_course_draft.py`。已装填旧的 40 节点课程时运行
`python -X utf8 scripts/connect_linuxlab_course.py`，仅添加新内容与映射，保存草稿历史，不覆盖原有教师编辑，
不发布课程。新增编号冲突时停止合并。重复运行不重复添加。

## 验证

诊断策略 `linuxlab-evidence-diagnosis-v3` 也处理已知原生命令的非零退出码，
即使学习者纠正后才运行 `lab check`，仍保留失败—查阅/求助—后续操作—检查结果的案例。
案例使用首条失败操作序号作为稳定标识；同关、同命令与操作数角色的连续失败合并，
现场恢复截断关联。退出码、粗粒度角色和检查结果不能证明具体失败原因或概念掌握。
命令执行次数与检查次数分开；重叠检查/输入案例关联展示，不作为独立知识错误累加。
`scripts/refresh_linux_assessments.py` 同时检测评估与诊断策略版本，只重放已导入的原始报告，
保留原始证据、课程图谱和历史版本，不采集尚未同步的操作。

```powershell
python -X utf8 -m unittest discover -s tests -p 'test_linux*.py'
python -X utf8 tests/test_ui_linux_lab.py
python -X utf8 tests/test_ui_linux_course.py
```

浏览器验收使用临时 PLIAC 存储和临时 Linux HOME，通过真正的桥接启动进入 Bash，
制造输入错误与错误备份，再确认网页知识关联、诊断、原话保存和导出。
正式课程同步、身份/版本隔离、历史保留、重复同步、提示等级及掌握限制以明确标为 synthetic 的隔离测试验证。
LinuxLab 另运行完整 WSL 回归，并重建、核验学生发行包；不创建新版本标签或 Release。
