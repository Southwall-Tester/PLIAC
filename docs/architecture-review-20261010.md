## 2 知识图谱：主要给智能体，也给学生看——对

| 使用者 | 用途 | 代码位置 |
|---|---|---|
| 智能体（主） | 先修关系决定学习顺序和前置补学 | `workspace._choose_node`（只用 prerequisite 边）、`recommendation.recommend_resources` |
| 智能体（主） | 节点是证据、诊断、复习、资源、讲义的公共锚点 | `course_graph`、`learner.states` |
| 智能体（主） | 规划学习范围、讲解时读取相邻概念与易混点 | `learning_plan`、`tutor.teaching_context` |
| 学生（辅） | 认知地图：看到自己在哪、哪里亮了、点节点让智能体安排 | `StarMap`/`GraphCanvas` |

结论：图谱的质量标准应以“智能体能否据此正确排序、定位缺口、回溯”为主，视觉冲击是次要目标。

“震撼感”下降的原因是示范课只有 30 个概念，原先那张大图是计算机组成整本书的 500 节点候选共现图。后者数量多，但关系质量不足以指导教学。

本轮已改为默认显示整门课并提供全屏。后续想要更强的视觉效果，可以把“课程概念图 + 讲义概念 + 资源节点”三层叠加在全屏视图里，由智能体只读其中经过核验的部分。

## 3 知识库：有，但还是“结构化课程内容”，不是独立检索库

已有的部分：
- 节点讲解：`lesson_content`、`description`、`objectives`。
- 来源文档与片段：`documents.py`、`source_reading.py`，可按页、段落回到原文。
- 检索：`retrieval.retrieve_sources`，在课程来源中检索，为讲解提供依据。
- 讲义产物：LearnMargin 产出的 `lesson.json`、`knowledge-map.json`。
- 资源目录：本轮新增。

还缺的部分：
- “定义/例题/易错点/案例”按节点结构化的条目库。
- 多本教材对齐到同一套框架。
- 常见错误类型库（v7 3.2 要求）。

对首轮来说，不必上向量数据库，按节点组织的 JSON 条目库就够了（v7 3.4 也允许）。

## 4 讲义生成的路径与形式：方向对，差一层“个人化”

目前有两条路径：

1. **课程讲义（课程级）**：资料经 LearnMargin 提炼成概念与讲义正文，经核验后生成。所有人看到的是同一份。
2. **智能体讲解（个人级）**：`teaching_flow`/`tutor` 按目标、画像、证据逐节生成，符合 v7“逐步生成、不预先固定整套个性化讲义”。

问题与调整：
- 课程讲义应作为**素材与依据**，而不是学生的最终读物。学生看到的应是智能体基于它的个人版本：
  - 跳过已掌握段落；
  - 按偏好替换案例；
  - 在薄弱点处展开。
- v7 要求的“标黄不懂 → 统一提交 → 逐条解读”：后端已有 `workspace.annotate`（标记原文 + 困惑 → 证据），但**前端没有入口，智能体也没有逐条回应**。这是最该补的一步，成本低，且直接体现千人千面。
- 质量问题（引用、边核验）按你的意见放到后期。

## 5 多模态与认知诊断：都“存在”，但多模态没进教学循环

| 层 | 状态 |
|---|---|
| 证据 → 诊断 → 状态分层保存，提示等级记为证据 | 有（`course_graph`、`assessment`、`workspace.hint/answer`） |
| 掌握状态四色、点击看依据 | 有（星图节点卡 Basis） |
| 间隔复习（可配置间隔、到期复测、通过后延长） | 有（`review_policy.intervals_days`、`spaced_retest`） |
| BDI 对话知识结构评估 | 部分（`tutor_quality`；未在页面呈现） |
| 摄像头授权采集、时间线、后台回看 | 有（`media*`、CameraPanel） |
| 输入删除/停顿等过程线索 | 无 |
| 多模态 → 智能体决策（如长时间停顿后询问是否需要帮助） | 无 |

建议先“存在、可记录、只作辅助”：

1. 在检验与实验输入框记录编辑、删除、停顿事件；
2. 由规则生成“可能卡住”的提示信号，交给智能体决定是否追问；
3. 诊断层只把它记作辅助证据，不改掌握状态。

科学验证放到首轮试用之后，采用 design-vs-implementation 2.5 中的三条件对比。

## 6 智能体在哪里、做什么

| 环节 | 智能体动作 | 位置 |
|---|---|---|
| 进入 | 目标协商、起点判断、规划学习范围 | 首页 → `learning_plan`、`workspace.onboard` |
| 每节 | 选下一节点（含补学、复测）、生成讲解、推荐材料 | `/api/tutor/flow`、`teaching_flow`、`resources` |
| 对话 | 受控讲解、追问、分级提示（讲解阶段完整，检验阶段限答） | `tutor`、TutorPanel |
| 检验 | 评判作答、写证据、更新诊断 | `assessment` |
| 实验 | 分级提示、记录提示程度 | `ml_lab` |
| 章末 | 章节报告、知识手册 | `workspace.chapter_reports/handbook` |
| 建课 | 资料 → 概念与讲义 → 自动核验 | `margin`、`margin_graph`、`knowledge_activation` |

缺口在于：学生多数时候是在点按钮，智能体的“下一步建议”还不够主动。

目标形态是：每完成一个动作，智能体都给出一句**带依据的下一步**（例如“你在『验证集作用』上用了 2 级提示 → 建议换个案例再练一题”），学生可以接受，也可以改选。数据已经存在（`teaching action` 的 `reason`），主要是前端呈现和统一调度。

## 7 v7 闭环对照

| v7 闭环 | 状态 |
|---|---|
| 进入与状态恢复（新人起点画像 / 老用户恢复并核验） | 有 |
| 章内：学习 → 诊断 → 调整下一小节 | 有 |
| 章内：知识点后安排情境实训 | 部分。实验存在，但不是由智能体在节点后自动安排；情境是预写的，未按兴趣生成 |
| 实训错误归因到知识点（错误类型库） | 无。目前只有分级提示，没有错误类型库 |
| 个人知识手册 | 部分。有数据，生成规则简单 |
| 章际：达标检查 → 补学复测 / 下一章 / 阶段报告 | 部分。`remediate`/`retest` 模式与章节报告有；达标规则和“下一章”切换不显式 |
| 跨章回溯（沿先修找历史薄弱点串讲） | 部分。选节点时优先 `needs_review`；“在当前小节串讲”未做 |
| 断点续学 | 有（学习位置、草稿、实验会话） |
| 间隔复习 | 有（固定间隔规则） |
| 多形态材料 + 推荐 + 记录选择 | 有（本轮补齐视频与课件） |
| 标黄提交 → 逐条解读 | 后端有，前端与智能体回应无 |
| 受控输出与分级提示 | 有 |
| 多模态辅助 | 采集与回看有；过程线索与进入决策无 |

v7 需要调整的地方：
- v7 写“正式入库前必须人工核验”，但现在的方向是**自动核验后生效、人只管标准与工具**。建议把 v7 3.2 改为：
  - 自动核验后生效；
  - 人工抽查；
  - 证据不足的条目保持候选状态。
- “情境由 AI 生成、骨架人工审核”的解耦可以保留，这是诊断可比性的基础。

## 8 可借鉴：OpenMAIC 与 DeepTutor

**OpenMAIC**（清华 THU-MAIC，MIT 许可）
- 机制：先生成大纲，再把每一项生成为一个“场景”。场景类型包括幻灯片配讲解、测验、交互模拟和项目式学习。
- 其他能力：白板、AI 教师与 AI 同学讨论、21 种动作的播放引擎。
- 它没有学习者建模，这正是我们的长处。

值得借鉴的：
1. **“大纲 → 场景”两段生成**：对应我们“学习计划 → 逐节生成”。可以把一节拆成几种场景类型（讲解卡片、互动模拟、短测、实验），由智能体按证据选择组合。这是“智能体全程驱动”最直观的形态。
2. **互动模拟（HTML）**：例如“拖动多项式次数看训练/验证误差”，比视频更适合欠拟合/过拟合。可以由智能体生成，或者先手写 2–3 个。
3. **AI 同学**：当前可暂不做（不做社区，但虚拟同学提问可作为后续“辨析”形态的候选）。

**DeepTutor**（港大 HKUDS，Apache-2.0，本地有副本）
- 值得借鉴的：
  1. **沉浸式视频学习**：B 站/YouTube 链接配合字幕检索、按时间点提问、笔记与续播。正好接上本轮的视频目录。
  2. **沉浸式阅读**：文档放在对话旁、逐页引用，对应我们的讲义 + 来源对话框，可以借鉴它的划词操作，做“标黄 → 解读”。
  3. **三层记忆**：L1 原始痕迹、L2 摘要、L3 综合，且可查看、可编辑，并用记忆图把结论连回证据。这与我们“证据 → 诊断 → 画像”同构，可以借鉴它的可视化，让学生看到“智能体为什么这样认为我”。
  4. **Mastery Path 的掌握门槛**：作为章际达标检查的参照。
- 不借鉴的：社区/EduHub、IM 伙伴、多引擎 RAG（对首轮过重）。

## 9 整体学习路径是否清晰

后端主线是清晰的：

```
目标 → 起点 → 计划 → 逐节（讲解/材料/对话 → 检验/实验 → 诊断）→ 章末报告 → 补学或下一章 → 间隔复习
```

学生侧还不够清晰，原因有三：
1. 页面上没有一条一直可见的“我在路径的哪一步、下一步是什么”；
2. 实验、章节报告、复习这些环节需要学生自己找入口；
3. 智能体的下一步建议分散在各处。

建议在学习页顶部加一条**学习路径条**，并配一句智能体给出的带依据的下一步：

```
本章：○ 已学 4/7 ── 当前「验证集的作用」：讲解 ✓ → 练习 ● → 实验 ○ → 小结
```

## 10 建议的下一批任务（按价值/成本排序）

1. 学习路径条 + 智能体“下一步”统一呈现（第 6、9 节）。
2. 标黄 → 逐条解读：前端划词入口 + 智能体逐条回应，复用 `annotate`。
3. 节点学完后由智能体安排实验或短测，并在章末给出达标判定与分支。
4. 过程线索记录（输入、删除、停顿）→ 作为辅助信号交给智能体。
5. 视频片段时间点与字幕；1–2 个欠拟合/过拟合交互模拟。
6. 按节点的知识条目库与常见错误类型库（首轮 3 个实训骨架）。
7. 个人讲义：基于课程讲义按画像改写。
