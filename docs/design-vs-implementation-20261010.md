## 1 平台架构（目标）

```
                ┌──────────── 知识构建闭环（智能体提炼 → 自动核验 → 可用版本 → 按缺口修订）────────────┐
多源资料 ──→ 知识与资源服务：知识框架（图谱）+ 知识库（定义/解释/例题/来源）+ 资源（讲义/视频/课件/Lab 任务）
                                        │ 共同依据
学生 ──→ 学习工作台 ──事件──→ 智能体运行层（教学主控 · 教材生成 · 教学交互 · 实践辅导 · 认知诊断 · 过程观察）
  ↑            │                         │ 教学动作                         │ 诊断
  │            └── 多种学习形式 ←────────┘                                  ↓
  └──────────── 个人状态（证据 → 诊断 → 画像/记忆）←──── 多模态与过程证据（授权）
                └──────────── 个性化教学闭环（了解 → 决定 → 生成 → 实践观察 → 诊断 → 再决定）────────────┘
```

三层数据：共享课程知识框架（不随学生改写）／个人知识状态（随证据更新）／个人教学方案（智能体生成、滚动调整，学生可协商）。

## 3 最主要的差距（按对“最初设想”的偏离程度）

1. ~~多种材料缺内容~~：示范课已录入视频与图文目录（2026-10-10）；仍缺片段时间点与字幕。
2. **多模态没有进入教学循环**：只采集不使用，与“观察—判断—调整—再验证”的核心价值脱节。
3. **知识框架尚未由多份资料提炼对齐**：目前一门课一份来源；“教材多样、框架同一”的核心理念还没有在数据上体现。
4. **讲义与情境未个性化**：千人千面目前主要体现在智能体讲解，课程讲义与 Lab 情境仍是统一内容。
5. **正式课未生效**：自动核验策略未定。
6. **验证体系未建立**：缺过程线索记录、前后测和对照条件。

## 4 建议的下一步顺序

1. 学习路径条与智能体“下一步”统一呈现；标黄→逐条解读（详见 `architecture-review-20261010.md` 第 10 节）。
2. 记录过程线索（输入修改、停顿、提示使用），并让智能体在实验与检验中据此“先追问、再提示”。这是“观察—判断—调整—再验证”的最小闭环。
3. 围绕“模型选择与过拟合”设计首轮验证：前测、学习、独立迁移后测；对照条件为同内容的一般 AI 帮助。
4. 讲义个性化：在课程讲义之上为学生生成个人导读，或按画像生成讲义变体。
5. 多份资料对齐成一套框架：至少两本教材/两套公开资料对同一单元提炼并合并。
