# 离线运行数据备份与恢复

## 1 范围与前提

1. `scripts/runtime_backup.py` 只备份显式指定运行根目录下的 `course_graph` 和 `documents`。包括其中实际存在的课程快照、资料文件、学习记录、身份和任务数据库、授权媒体等；不会自动寻找其他自定义存储路径。
2. 操作前必须正常停止所有写入这些目录的服务与任务。`--confirm-offline` 是操作者的确认，不是程序已经证明服务停止。写锁及前后校验只能发现部分并发变化，不提供热备份或数据库事务快照保证。
3. 配置、密钥、代码、种子课程和前端构建不包含在此快照内。它不是完整部署包；恢复需要匹配版本的应用及单独保管的必要配置。未提交代码和未跟踪文件仍需独立保全。
4. 备份没有加密，也不会扫描或清除资料中意外包含的秘密。学习记录和视频仍属需保护的数据；使用受控位置，按原授权与留存要求管理，不能上传公共仓库。

## 2 操作方式

在仓库根目录使用本项目 Python 运行以下模板，先将尖括号内容替换为明确的绝对路径。不要直接执行未替换模板。

```powershell
.venv/Scripts/python.exe scripts/runtime_backup.py backup "<已停止写入的运行根目录>" "<独立且尚不存在的备份目录>" --confirm-offline
.venv/Scripts/python.exe scripts/runtime_backup.py restore "<备份目录>" "<独立且尚不存在的恢复目录>"
```

1. 来源与目标不能互相嵌套；目标存在则拒绝，不覆盖任何现有记录。目录符号链接与 Windows junction 被拒绝，普通 Windows 短路径别名可用。应在没有其他进程修改目录结构的受控环境操作。
2. 备份逐文件计算 SHA-256，复制后复核，并再次检查来源清单及内容。最后才写 `manifest.json`。失败可能保留不完整目录，程序不自动删除；没有完成清单的副本不能恢复。
3. 恢复先检查文件清单与摘要，再创建新目标并复制复核。摘要用于检测损坏，不是数字签名，不能防止攻击者同时替换文件和清单。
4. 恢复完成只产生一个新的数据目录，不切换服务、不启动任务、不调用模型，也不覆盖线上目录。恢复出的未完成任务与授权媒体需按实际部署规则检查，不能无审查地连到外部服务。
5. 切换应用前检查课程版本、学习记录、资料读取及数据库完整性，在隔离配置下演练后再安排切换。恢复出的备份不会延长媒体授权或保存期限，已经撤回或应删除的数据不得直接重新开放。

## 3 验证边界

自动测试使用临时合成数据，覆盖 SQLite 完整性、真实 CourseGraphStore 的课程与学习者恢复以及继续保存、旧目录保护、清单越界、内容损坏、写锁和复制期间变化。没有对当前用户运行数据执行备份或恢复，不代表正式部署恢复演练已完成。
