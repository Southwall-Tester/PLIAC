# 摄像头存储开发边界

本模块已接入工作台的可选授权与分段采集，但不是可开放真实试用的完整功能。默认关闭，尚未采集任何真实摄像头数据。

## 1 开启条件

1. `PLIAC_REQUIRE_AUTH=1`，必须使用服务端登录身份；开发模式下的任意学习编号不能发起媒体操作。
2. `PLIAC_MEDIA_ENABLED=1`，由部署者显式设置。
3. `PLIAC_MEDIA_RETENTION_DAYS` 必须显式指定为 1 至 30 的整数，未设置不默认留存。
4. `PLIAC_MEDIA_CONTACT` 必须指定有效的负责联系信息。测试中的 synthetic contact 不是正式联系人。
5. 上述配置只是代码开关，不代表授权安排、备份删除、校内程序、容量或播放器安全验证已完成。真实启用前还需完成这些准备并取得用户确认。

## 2 接口契约

1. `GET /api/media/policy` 提供当前用途、限制、期限、联系信息和内容指纹版本。
2. `POST /api/media/start` 必须带本人 student_id、稳定 request_id、activity_kind、activity_id、accepted=true 及当前 policy_version。仅允许已保存且属于当前课程版本的教材、核验或实验活动。
3. `POST /api/media/upload` 接受 session_id、从零递增的 sequence、会话内相对 start_ms、duration_ms 和独立 WebM 的 base64 内容。同序号相同内容幂等，不同内容拒绝。每片段不超过 1 MB／20 秒、会话不超过 50 MB；这是开发上限，不是并发容量证明。
4. `POST /api/media/control` 的 operation 可为 pause、resume、stop、revoke。暂停拒绝上传；停止保留可回看片段；撤回删除片段；关闭、撤回、到期不能直接恢复旧采集。
5. `GET /api/media/session` 返回本人会话及片段时间索引；`GET /api/media/clip` 返回本人片段，均须带本人 student_id 与 session_id。片段读取不能仅凭会话编号。
   `GET /api/media/sessions` 列出当前课程本人最近的会话（上限 100），包括结束、到期和撤回记录，不返回其他学生或视频字节。
6. 接口均通过 course_id 解析课程存储，不能把其他课程活动绑定到本课程；课程更新后停止接受旧版本上传。
7. 普通管理员不能代替学生同意授权或撤回。后台回看须同时启用受保护模式和 `PLIAC_MEDIA_REVIEW_ENABLED=1`，并使用管理登录；默认不开启。`GET /api/media/review/sessions`、`session`、`clip` 是只读接口，保留本人接口原有的归属、到期和撤回检查。学生不能使用后台接口，管理员不能借回看权限改动学生记录。
8. 管理身份从“账户与访问”进入 `/app/media-review`，按课程编号和学习者匿名编号查询，不全量枚举学生。当前管理凭证授予的是部署级回看权限，尚未实现逐管理员、逐课程的精细授权，不能分发给不应访问全部受管课程的人员。
9. `review_access` 记录管理身份、目标学习者、会话、操作（含片段编号）与请求时间，表示访问尝试而非保证播放成功；不记录凭证或原视频。审计留存、轮换和独立审计界面尚待部署治理。

## 3 存储与删除

1. 媒体独立保存到课程输出目录 camera.sqlite3，不进入原始学习作答、诊断、模型提示、报告导出或普通文本日志。
2. 记录会话活动关联、客户端相对片段时间和服务端接收时间。两类时间不冒充已经校准的精确跨设备时钟。
3. 撤回删除该会话片段；服务启动时及运行期间每 60 秒检查到期片段，即使关闭采集配置仍继续清理已有数据。范围限定默认课程、UUID 课程目录及固定演示课程的 camera.sqlite3，拒绝重定向目录；不递归扫描其他文件。读取接口仍独立清理并拒绝到期数据。服务停止期间无法定时执行，重启时补清；数据库锁或异常会记录警告并在下轮重试，因此不能承诺到期瞬间物理删除。
4. SQLite 开启 secure_delete，但不承诺覆盖文件系统快照、磁盘恢复区或独立备份。备份中的删除流程必须由部署方案明确。
5. 最小授权及状态记录在撤回后仍保留，供阻止迟到上传与说明操作状态；完整账户删除与元数据期限尚待实现。

## 4 尚待完成

1. 浏览器已实现明确授权、预览、分段上传、暂停释放设备、停止、撤回、隐藏页面与离开活动时关闭。会话编号按标签页保存，不存视频；已通过模拟设备主路径。设备拒绝、刷新及多标签竞争仍需扩充验证，完整会话所有权协调尚未完成。
2. 服务端已增加 ffprobe 媒体流检查及 ffmpeg 完整解码：只允许单个 VP8/VP9 视频流，拒绝音轨、额外流、超大尺寸、超长时间、无帧或解码失败。缺工具时拒绝保存；工具须在部署 PATH 中提供。已用浏览器 Canvas 纯色片段通过真实解码，不代表真实设备兼容性或完整采集界面已通过验证。
3. 本人可在暂停采集后选择历史会话、查看活动编号和相对片段时间、播放独立片段或撤回删除；关闭采集配置后仍可管理历史记录。授权后台已具备单独只读入口。真实浏览器已验证本人及后台模拟设备视频播放、本人撤回后后台刷新清空。与详细学习事件联动的时间线、跨标签撤回时已下载播放器的及时失效仍待补齐；不能声称服务器撤回可以收回已经下载的副本。
4. 定时清理已接服务生命周期，临时数据验证无人访问也会删除、未到期不删除、单库异常不阻断其他库、服务关闭停止任务。仍需全局容量限制、部署级清理故障告警、备份恢复与删除演练，以及真实多人并发测试。
5. 基础线索只触发询问，不诊断心理状态；不得将摄像头拒绝、设备错误或缺失片段转成负面能力证据。

当前测试使用隔离临时数据库、合成身份、协议模拟及浏览器 Canvas 测试片段，没有打开摄像头或麦克风，没有上传到模型。解码在数据库事务之外进行，完成后重新核查授权与状态，防止校验期间撤回后仍写入。单次探测与解码分别限时 10 秒和 15 秒；尚未配置跨请求的解码并发池或操作系统资源沙箱，不能据此宣称可安全承载公开上传。
